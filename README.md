# dpcp — Dynamic Port Configuration Protocol

A host-central port broker for working directories. Declare your
services and default ports in a `dpcp.yml` file, then run
`dpcp allocate` to get a unique, collision-free set of host ports.
Assignments are stored in `~/.dpcp.sqlite` and written to a gitignored
`.dpcp.env` file that docker-compose, clients, and/or other software
read at startup.

It skips ports already bound on the host (by Docker, bare-metal
servers, or anything else), so allocations are collision-free even
across projects.

## Install

```sh
cargo install --path .
```

## dpcp.yml

Place a `dpcp.yml` in your working directory to declare your services:

```yaml
env-file: .dpcp.env        # optional; path relative to dpcp.yml, or absolute

ports:
  postgres:
    default-port: 5432
  redis:
    default-port: 6379
  myservice:
    default-port: 8080
    protocol: http          # optional; http or https — emits a full URL in .dpcp.env
    env-name: MY_SVC_PORT   # optional; overrides the generated env var name

env:                        # optional; arbitrary extra vars written as-is to .dpcp.env
  APP_ENV: local
  FEATURE_FLAG: "1"
```

| Field | Required | Description |
|---|---|---|
| `ports` | yes | Map of service name → port config |
| `ports.<name>.default-port` | yes | Starting port; dpcp increments if taken |
| `ports.<name>.protocol` | no | `http` or `https` — writes `http://127.0.0.1:<port>/` instead of a bare number |
| `ports.<name>.env-name` | no | Override the env var name (default: `<NAME>_PORT`) |
| `env` | no | Map of extra env var name → value, written as-is to `.dpcp.env` |
| `env-file` | no | Path to write `.dpcp.env` (default: `<workdir>/.dpcp.env`) |

Add `.dpcp.env` to your `.gitignore` — it's host-specific and must not be committed:

```
.dpcp.env
```

## Usage

```
dpcp allocate <workdir>
dpcp release  <workdir>
dpcp list
dpcp gc
```

### allocate

```sh
dpcp allocate .
```

Reads `dpcp.yml` from `<workdir>`, allocates a host port for each
service starting from its default, and writes the results to `.dpcp.env`:

```sh
# Generated by dpcp — do not edit by hand
# Working directory: /path/to/your/working/directory
POSTGRES_PORT=5432
REDIS_PORT=6380
# ^ redis default 6379, allocated 6380
MY_SVC_PORT=8081
# ^ myservice default 8080, allocated 8081
```

Idempotent — re-running for an existing working directory returns the
same ports.

**Without dpcp.yml** — services can be passed directly on the command
line as `name:default-port[:scheme]`:

```sh
dpcp allocate . postgres:5432 redis:6379 myservice:8080:http
```

This is handy for one-off use, but `dpcp.yml` is the recommended
approach for projects: it keeps the service list version-controlled
alongside your `docker-compose.yml` and removes the need to repeat the
port list in every script that calls `dpcp allocate`.

### release

```sh
dpcp release .
```

Frees all port allocations for the working directory. Safe to call on
already-deleted paths.

### list

```sh
dpcp list
```

Shows all current allocations grouped by working directory.

### gc

```sh
dpcp gc
```

Removes allocations for working directories whose paths no longer
exist on disk. Run this periodically if you delete working directories
without calling `release`. (For example, upon exiting a `claude
--worktree` session).

## Wiring up a bare-metal application

Allocate ports and source the env file before starting your application:

```sh
dpcp allocate .
source .dpcp.env
./myapp --port "$MYSERVICE_PORT" --db-port "$POSTGRES_PORT"
```

Or in a single line:

```sh
dpcp allocate . && source .dpcp.env && ./myapp
```

The env vars are available to any process started in the same shell session after sourcing.

## Wiring up docker-compose

Reference the dpcp variables in your `docker-compose.yml` with
fallbacks to the service defaults:

```yaml
services:
  postgres:
    image: postgres:16
    ports:
      - "${POSTGRES_PORT:-5432}:5432"

  redis:
    image: redis:7
    ports:
      - "${REDIS_PORT:-6379}:6379"

  myservice:
    build: .
    ports:
      - "${MYSERVICE_PORT:-8080}:8080"
```

## Wiring up a Justfile

```just
up:
    dpcp allocate .
    docker compose --env-file .dpcp.env up -d

down:
    docker compose --env-file .dpcp.env down
    dpcp release .
```

With this setup, every working directory gets its own isolated port set
automatically.  `just up` on two working directories side-by-side just works.

## Wiring up a Makefile

Make's dependency tracking lets `.dpcp.env` regenerate automatically whenever
`dpcp.yml` changes:

```make
.dpcp.env: dpcp.yml
	dpcp allocate .

up: .dpcp.env
	docker compose --env-file .dpcp.env up -d

down:
	docker compose --env-file .dpcp.env down
	dpcp release .
```

## Garbage collection

Working directory deletion doesn't automatically release ports (there's no reliable
cross-platform hook for it). Run `dpcp gc` occasionally to reclaim ports from
deleted working directories, or wire it into your shell's workdir-deletion alias:

```sh
# ~/.zshrc or ~/.bashrc
gwt-delete() {
    dpcp release "$1"
    git worktree remove "$1"
}
```
