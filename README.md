# dpcp — Dynamic Port Configuration Protocol

A host-central port broker for working directories. When you have multiple
working directories running network stacks, dpcp hands each one a unique set of
host ports, stores the assignments in `~/.dpcp.sqlite`, and writes a
gitignored `.dpcp.env` file that Compose reads at startup.

It skips ports already bound on the host (by Docker, bare-metal
servers, or anything else), so allocations are collision-free even
across projects.

## Install

```sh
cargo install --path .
```

## Usage

```
dpcp allocate <workdir> <service:default-port>...
dpcp release  <workdir>
dpcp list
dpcp gc
```

### allocate

```sh
dpcp allocate . postgres:5432 redis:6379 myservice:8080
```

Allocates a host port for each service, starting from the given
default. If the default is already taken (by dpcp or anything else
bound on the host), dpcp increments until it finds a free port. Writes
the results to `.dpcp.env` in the working directory:

```sh
# Generated by dpcp — do not edit by hand
# Working directory: /path/to/your/working/directory
POSTGRES_PORT=5432
REDIS_PORT=6380
# ^ redis default 6379, allocated 6380
MYSERVICE_PORT=8081
# ^ myservice default 8080, allocated 8081
```

Idempotent — re-running for an existing working directory returns the same ports.

### release

```sh
dpcp release .
```

Frees all port allocations for the working directory. Safe to call on already-deleted
paths.

### list

```sh
dpcp list
```

Shows all current allocations grouped by working directory.

### gc

```sh
dpcp gc
```

Removes allocations for working directories whose paths no longer exist on disk. Run this
periodically if you delete working directories without calling `release`.

## Wiring up docker-compose

Reference the dpcp variables in your `docker-compose.yml` with fallbacks to the
service defaults:

```yaml
services:
  postgres:
    image: postgres:16
    ports:
      - "${POSTGRES_PORT:-5432}:5432"

  redis:
    image: redis:7
    ports:
      - "${REDIS_PORT:-6379}:6379"

  myservice:
    build: .
    ports:
      - "${MYSERVICE_PORT:-8080}:8080"
```

Add `.dpcp.env` to your `.gitignore` (it's project-specific and must not be
committed):

```
.dpcp.env
```

## Wiring up a Justfile

If you use a Justfile, it should own the canonical list of services
and their defaults. Pass them to dpcp before bringing Compose up:

```just
up:
    dpcp allocate . postgres:5432 redis:6379 myservice:8080
    docker compose --env-file .dpcp.env up -d

down:
    docker compose --env-file .dpcp.env down
    dpcp release .
```

With this setup, every working directory gets its own isolated port set
automatically.  `just up` on two working directories side-by-side just works.

## Garbage collection

Working directory deletion doesn't automatically release ports (there's no reliable
cross-platform hook for it). Run `dpcp gc` occasionally to reclaim ports from
deleted working directories, or wire it into your shell's workdir-deletion alias:

```sh
# ~/.zshrc or ~/.bashrc
gwt-delete() {
    dpcp release "$1"
    git worktree remove "$1"
}
```
